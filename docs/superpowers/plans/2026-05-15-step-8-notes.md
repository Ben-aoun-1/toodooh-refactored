## CF-1 — Sed-pattern coverage checklist (Adjustment A)

Before running sed for any feature commit, enumerate which **three import-path
shapes** are in play for the files being moved:

1. **External imports** from outside the moving directory: `'../X'`, `'../../X'`,
   `'../../../X'`, etc. The exhaustive external-directory list is:
   - `lib/`, `assets/`, `services/`, `stores/`, `types/`, `pages/`
   - `components/`, `hooks/`, `contexts/`
   - **`constants/`** (added after Commit 1 caught it missed)
   - `utils/`, `data/`
   - `features/` (for cross-feature imports after auth lands)

2. **Self-sibling imports** inside the moving directory: `'./X'` patterns.
   These are subtle and easy to miss because sed default patterns look for `..`.
   Commit 1 missed `./admin.store` in `stores/auth.store.ts` — when
   `stores/auth.store.ts` moved out of `stores/`, its `'./admin.store'` sibling
   reference broke (now needs `'../../../stores/admin.store'`).

   **Per-commit check:** grep for `from '\./` in each moving file before sed:
   `grep -nE "from '\./" <file>` — any hit needs rewriting.

3. **Intra-feature siblings post-move** become `'./X'` again automatically when
   the relative depth lines up (e.g., `features/auth/components/LoginForm.tsx`
   importing `'../stores/auth.store'`). Trust git rename detection here; no
   sed needed.

**Surface in pause summary:** under spot-check or surprises, state which shapes
were in play and whether all three were handled.

## CF-2 — Standard four-gate cadence with sed-aware autofix (Adjustment B)

The four-gate cadence in practice for Step 8 is:

```
typecheck → sed → (eslint --fix scoped to touched files) → lint → test → build
```

**Why the autofix step is routine, not regression-tolerance:**
sed-injected `features/*` paths land at the original line positions. Alphabetical
sort then requires reordering on every consumer of every moved file. This appears
as a temporary `import-x/order` lint spike on every Step-8 commit.

**Procedure:**
1. After sed, run `pnpm exec eslint --fix $TOUCHED_FILES`.
2. Then measure the lint gate against post-autofix state.
3. Lint must return to baseline 370.

**Halt-condition refinement:**
- Order-only spike → routine, fix with autofix, proceed.
- **Spike survives autofix** (some non-order rule regressed) → halt and
  investigate. THAT is the real regression signal.
- Per Commit 1: `import-x/order` was the entire +35; autofix returned lint to 370
  cleanly. No other rules regressed. Expected pattern.
