## Section 4 — Per-commit verification gates

Four-gate cadence between every commit:

- **typecheck** must stay **51**. Step 11 edits JSX markup; it should
  introduce no type errors. If a fix genuinely needs a type narrowing/
  assertion (rare — e.g. an event-handler signature change), surface it
  per CF-5-extended with a stash-diff. Movement off 51 → hard-halt.
- **lint** — errors must **decrease by exactly the commit's rule-family
  count**; no other rule family may regress (warnings included). The
  commit's pause summary states the before/after per-rule counts.
- **test** must stay **160 / 21 suites / 0**. Step 11 adds no tests. If a
  markup fix breaks an existing test (a fix changing runtime behaviour),
  that is a regression — surface, revisit the fix shape, do not edit the
  test to pass.
- **build** — main `index-*.js` gzip **139.60 ± 0.5 kB**; per-chunk
  ± 0.5 kB. Markup changes are near-zero bundle impact.
- **file count 236** — Step 11 modifies existing files; **no new files**.
  A new file appearing → halt (see §6).

`pnpm exec eslint --fix` on touched files is **not** the autofix lever it
was in Step 8 — none of the Step 11 target rules is eslint-autofixable.
Fixes are hand-applied. `prettier --write` via `lint-staged` may still

## Section 6 — Hard-halt conditions

Stop, do not commit, surface, if:

1. **typecheck moves off 51** without a CF-5-extended-justified cause.
2. **A non-target rule family regresses** during a sweep (lint error count
   for any rule *other than* the commit's target goes up).
3. **An existing test fails** in a fix-touched file.
4. **A "mechanical" fix surfaces a judgment call** mid-execution — halt,
   surface, re-categorize the occurrence into the judgment commit.
5. **A fix introduces a runtime regression** visible on inspection — e.g. a
   keyboard handler added for `click-events` conflicts with existing
   navigation; a `<div>`→`<button>` conversion changes layout or nests a
   button inside a button.
6. **A fix appears to need a new file / an extraction** — Step 11 is
   in-place markup edits; an extraction is out of scope → surface as a
   "scope decision needed".
7. **An `exhaustive-deps` fix would change observable behaviour** (adding a
   missing dep causes new re-runs; the effect was relying on the stale
   closure) → halt, classify (intentional-omission-with-`eslint-disable`
   vs genuine-bug), surface.
